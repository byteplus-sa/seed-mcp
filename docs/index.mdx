Finish local workflows with [object storage and artifacts](/seed-mcp/capabilities/#uploads-and-outputs)
and [existing Seedance asset references](/seed-mcp/assets/).

Start with anonymous static HTTP discovery before making a paid generation.
Both transports call tools directly, without MCP jobs or native tasks.
Storage and artifact resources remain local stdio only.
Seed TTS always saves its completed audio; other generation tools require
explicit local persistence.
Hosted HTTP is stateless and database-free, with multi-pod deployment support
and per-pod limits. Task access follows the supplied provider key, not the client
secret. Omit `idempotency_key`: supplied legacy keys are rejected on both
transports. There is no durable replay or shared budget accounting; repeated
creates may bill again. Save task IDs, poll, and never automatically resubmit
uncertain creates. Live deployment and provider/client acceptance remain
separate from source validation.
See the [submission contract](../specs/SPEC_HOSTED_BYOK.md#http-submission-safety).

## About This Server

Seed MCP is the focused image, video, audio and speech fork of Ark MCP.
It does not expose media understanding, dedicated ASR, 3D, VOD processing or
provider asset administration. Package/module names, the `ark-seed` client
entry and the `ark-mcp` skills remain unchanged for compatibility.

The repository has __TOOL_COUNT__ tool definitions across both transports;
the hosted connection exposes seven. This handbook tracks its build revision,
not necessarily the deployed instance. Use the
[connection guide](/seed-mcp/setup/install/) for the hosted URL, and the
[deployment record](/seed-mcp/hosted-deployment-status/) for dated live evidence.
This website is documentation, not the MCP endpoint itself.
